# AskSQL

Аналитика на естественном языке для одной разрешённой таблицы продаж.
Контур: вопрос → SQL → проверка AST → проверка стоимости плана → выполнение
ограниченной ролью PostgreSQL → результат и объяснение. Неоднозначный вопрос
возвращает уточнение; следующий запрос может ссылаться на предыдущий.

## Режимы генерации

По умолчанию `MODEL_MODE=demo`: детерминированные шаблоны для вопросов
«общая выручка», «выручка по товарам», «сколько продаж» и уточнения «выручка».
Этот режим проверяет инфраструктуру и не является LLM.

`MODEL_MODE=ollama` вызывает `/api/chat` локального Ollama с JSON-ответом и
температурой 0. Задайте `OLLAMA_URL` и `OLLAMA_MODEL` в окружении сервиса `api`
в Compose, заранее установив модель, затем пересоздайте контейнер API.
Проверка SQL одинакова для обоих режимов. Живой запуск Ollama в проверенном
окружении не выполнен: локальный сервер на порту 11434 недоступен.

## Ограничение доступа

Аналитическая БД отделена от БД истории вопросов. В API передаются только
учётные данные `report_a` и `report_b`; учётная запись владельца аналитической
БД API не нужна. Клиенты определяются по разным API-ключам, а роли — настройкой
сервера, не ответом модели.

В аналитической БД применяются RLS по текущей роли, права SELECT только на
`day`, `product`, `region`, `amount`, отсутствие прав создания и записи,
режим read-only, тайм-аут запроса 1 секунда, блокировки 250 мс и ограничение
временных файлов 1 МиБ. Попытка выключить RLS не раскрывает чужие строки.

SQLGlot разрешает один SELECT из `analytics.sales`, простые фильтры,
группировку и COUNT/SUM/AVG/MIN/MAX. JOIN, CTE, подзапросы, UNION, произвольные
функции, другие таблицы и `SELECT *` запрещены. `COUNT(*)` разрешён.
Ограничены длина SQL, число узлов AST, стоимость плана и результат до 100 строк.
Меньший пользовательский LIMIT сохраняется. Это намеренно узкий SQL-диалект.

## Запуск

```sh
docker compose up --build -d
curl -H 'X-API-Key: demo-a-key' http://localhost:8095/health
curl -X POST http://localhost:8095/ask \
  -H 'X-API-Key: demo-a-key' -H 'Content-Type: application/json' \
  -d '{"question":"общая выручка"}'
```

У первого клиента сумма — 450,00, у второго (`demo-b-key`) — 9999,00.
Это синтетические данные из `sql/analytics.sql`. Порты опубликованы только
на localhost. Пароли и ключи в Compose демонстрационные.

Для уточнения отправьте `{"question":"выручка"}`, затем
`{"question":"общая","parent":"UUID первого ответа"}`. Другой клиент не может
использовать чужой вопрос как родительский. Ответ имеет статус `completed`,
`clarification` или `refused`; отсутствие доступа — HTTP 401/404,
ошибка провайдера модели — 502. Схема API доступна на `/docs`.

## Проверки

Нужны Docker Compose и `uv`:

```sh
cp .env.example .env
set -a
. ./.env
set +a
uv sync --frozen
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
uv run python -m scripts.evaluate
```

Тесты истории создают временные схемы; аналитические проверки используют
изолированную демонстрационную БД. Проверяются 16 вариантов вредоносного SQL,
результаты обоих клиентов, уточнения, права роли напрямую, RLS и реальный
тайм-аут PostgreSQL. Ответ модели с `pg_sleep` отвергается до выполнения.
Демонстрационная оценка содержит обычные и провокационные вопросы; она оценивает
шаблонный режим, не качество LLM. CI запускает обе БД, API и весь набор проверок.

## Структура и ограничения

Python 3.11+, FastAPI, PostgreSQL 17, SQLGlot, httpx. `guard.py` проверяет SQL,
`model.py` содержит шаблоны и адаптер Ollama, `api.py` управляет выполнением,
`sql/analytics.sql` задаёт права и демонстрационные данные.

Одна таблица, четыре колонки и два клиента; нет JOIN, оконных функций и CTE.
Нет очереди запросов, лимита частоты и пула соединений. Ограничения отдельного
запроса не защищают от множества параллельных запросов. Объяснение формирует
модель или шаблон: оно не является доказательством корректности аналитики.
История хранит вопросы и результаты; перед применением к реальным данным нужны
политика хранения, аудит и персональные ключи. Администратор инфраструктуры
остаётся доверенной стороной. Скрипт инициализации аналитической БД выполняется
только на новом томе; изменение SQL не обновляет уже созданную БД автоматически.

Остановка: `docker compose down`. Данные томов сохраняются.
Документация: [SQLGlot](https://sqlglot.com/),
[PostgreSQL RLS](https://www.postgresql.org/docs/17/ddl-rowsecurity.html).
